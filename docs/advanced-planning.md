# Route planning data and offline packs

PilotDesk uses dated FAA CIFP editions for identifier resolution, airway expansion, and terminal procedure segment inspection. Set UTC departure before building to select the edition covering that departure. The API discovers published FAA ZIP links, validates the archive CRC and size, checks the dataset header cycle, and resolves fixes by record section and ICAO region. Missing or ambiguous coordinates stop expansion. Individual record amendment dates are not the dataset effective date.

Enter `CTB V430 AGRYN` or `KGFK DCT KFAR`. Expanded routes retain airway altitude fields. Published discontinuities, unresolved fixes and incompatible direction restrictions stop expansion. Editing an expanded route materializes its verified coordinates first. Airway geometry does not independently validate aircraft capability, altitude, NOTAMs or a clearance.

Procedure rows show the FAA path terminator and raw published altitude/speed constraint fields. Segments remain separate runway, common and enroute branches. IF/TF/DF segments can be inserted only with an exact existing route join. Vectors, holds, course-defined/curved paths, internal initial fixes, unresolved points and missed approaches are not automatically inserted. No straight connector is invented across unsupported paths. Read the full current chart.

Aircraft profiles can store a user-supplied POH table, documentation revision and configuration. Import verified CSV/JSON data, or enter numeric JSON rows with `pressureAltitude`, `oat`, `weight`, `cruiseTas`, `cruiseBurn`, `climbTas`, `climbBurn`, `climbRate`, `descentTas`, `descentBurn`, `descentRate`. Units: ft pressure altitude, degrees C, lb, TAS knots, US gal/hr and ft/min. No factory aircraft data is supplied. Interpolation uses the surrounding altitude/temperature/weight grid and requires every corner. Extrapolation and duplicate conditions are rejected. Cruise OAT, pressure altitude offset and temperature lapse are explicit flight inputs. Climb/descent use 500 ft midpoint bands; planning weight and each leg's wind remain constant. This cannot reproduce arbitrary POH chart shapes or engine operating limitations. Cruise leg overrides retain precedence.

Offline flight packs download the visible FAA chart bounds at the selected native source resolution, this planner's static dependencies, the resolved route, aircraft planning settings, navigation responses and attached same-origin FAA PDF links. Limits are 800 tiles and 100 MB per pack. The active service worker must advertise pack support. Every resource must succeed before a manifest marks the cache complete; cancellation and failure discard the new cache and preserve older packs. Cache prefixes are independent of the normal shell cache, so worker updates do not remove completed packs. Packs expire at the earlier of their navigation edition expiration and seven days after capture. Verify the chart's printed edition separately. Browser storage remains subject to eviction; open the pack with networking disabled before departure.

Weather, NOTAMs, TFRs and other live API results are not cached as current briefing data. Saved forecast winds are cleared when creating a pack. An offline pack is a planning aid, not an official briefing or avionics database.

Sources: [FAA CIFP](https://www.faa.gov/air_traffic/flight_info/aeronav/digital_products/cifp/download/), [FAA d-TPP](https://www.faa.gov/air_traffic/flight_info/aeronav/digital_products/dtpp/), [FAA raster charts](https://www.faa.gov/air_traffic/flight_info/aeronav/digital_products/). Field offsets were checked against the public [arinc424 reader definitions](https://github.com/jack-laverty/arinc424); the application parser is implemented locally without a third-party runtime dependency.

Validation: `node qa/advanced-planning-tests.mjs` and `node qa/route-performance-tests.mjs`. For the recorded FAA integration fixture, set `PILOTDESK_CIFP_FIXTURE` to the extracted `FAACIFP18` file. `qa/advanced-planning-browser.mjs` additionally requires Playwright/Chromium and recorded Leaflet JS/CSS paths. Its weather/PDF/tile fixtures are test-only; it checks actual service-worker offline reload, source route expansion and cache isolation. Physical phone/tablet field testing is outside this release.
